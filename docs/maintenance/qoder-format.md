# Qoder CN CLI format surface

Generated by `qcut format`. Everything this tool assumes about the
**Qoder CN CLI**'s own files (the IDE/app is out of scope). Re-verify after
a Qoder update; the procedure is in [`MAINTENANCE.md`](../../MAINTENANCE.md).

## Layout (relative to ~/.qoder-cn)

- transcripts: `projects/**/*.jsonl`
- skill manifests: `skills/**/SKILL.md`
- plugin index: `plugins/installed_plugins_v2.json, plugins/installed_plugins.json`
- MCP servers: `mcp.json`
- settings (BYOK routes): `settings.json`
- line separator: `b'\n'`

## Record types

- claimed: assistant, runtime-config, system, user, workspace-directories
- claimed and dropped: active-leaf, ai-title, attachment, custom-title, file-history-snapshot, last-prompt, worktree-state
- `system` subtype indexed: `compact_boundary` (metadata only; every other subtype is dropped)
- anything else is counted in `unparsed` as `type:<name>`

- inventory JSON: baseUrl, installPath, mcpServers, plugins, providers, source, version

## Token capture (environment)

- variable: `QODERCN_EXPOSE_TOKEN_USAGE=1`
- scope: the process that runs the Qoder CN CLI, not qcut
- unset: hosted routes write a literal 0 in every token field and real credits
- set: hosted routes write real input/output/cache-read/cache-creation tokens; credits may also be present
- past calls: already written with zeros and cannot be recovered by qcut

## Classification

- skill tool: `Skill` (arguments `command`, `skill`)
- agent tool: `Agent` (arguments `subagent_type`, `agent_type`; default `general-purpose`)
- mcp tools: `mcp_call` -> call, `mcp_get` -> get, `mcp_list` -> list
- mcp target: `mcp__<server>__<tool>` in the `toolName` argument
- custom route: `<providerId>/<model>`, prefix `qoder-custom-`

## Where a slash command comes from

Two fields, and they are not the same kind of evidence:

- `toolUseResult.commandName` on a `user` record. Observed on this machine: 2 records
  out of 181,907 lines, values `playwright-cli` and
  `qoder-context:qoder-context-knowledge-plan`. This is the only command source
  that has ever produced a row here.
- A `<command-name>name</command-name>` marker in the **text of a `user` record**.
  Qoder has not written one here yet, so the reader is a hypothesis about the
  format rather than a measured field -- it is kept because a marker that opens a
  user text block can only be an echo of an invocation.

The scan deliberately does *not* run over `assistant` text blocks. The marker
appears 7 times in the transcripts on this machine and all 7 are an agent quoting
the tag inside an explanation, including 4 in subagent transcripts, which
`projects/**/*.jsonl` indexes. Reading them as commands would record usage that
never happened, and it would store a slice of model prose -- the one thing this
tool never keeps. `test_sync.CommandTest` holds both halves of that line.
