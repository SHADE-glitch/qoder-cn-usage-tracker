# qcut — read-only audit report (2026-10-26)

> **A snapshot, not current state.** One-off read-only audit of
> `qoder-cn-usage-tracker` at `a64519f`, taken on 2026-10-26: full source reading, probes on a
> copy of the live database under `/tmp`, and a full test run. Nothing was installed and no
> repository file was modified during the audit. Repaired items carry **fixed in `<commit>`**;
> open ones are listed at the end.

- **Baseline**: `.venv/bin/python -m unittest discover -s scripts/tests -q` → **406 tests, OK**
  (251 s). 387 was the 2026-10-22 number; the 2026-10-25 round added 19. README, README.zh-CN and
  the run agreed, and `test_readme_counts` guards that.
- **Verdict**: aggregation and windowing are careful, and the "unknown is not zero" rendering
  holds. The failures are **a refusal that never fires** and **a page size reported as a total**.

### Evidence for the P1s

1. **The refusal that never fired.** Setting `meta.schema_version = 99` made `migrate()` raise as
   designed — but going through the real entry points (`run()`, `TrackerApp`) rewrote the marker
   to 3 first, after which `migrate()` returned "current". Every later build would read a newer
   database as its own.
2. **Page size as match count.** Against a copy of the live database, `filter "qfmodel"` matched
   50,902 rows and the page said `100 matches`; the unfiltered branch on the same screen already
   said `showing 100 of 50,902`.

### One bug found outside the audit list

The run-history row recomputed Usage Total from already-summed columns, so a run with a NULL
component displayed 73 where the header, the Agents tab and the CLI all said 33. The row now reads
the query's `usage_total_tokens`, and the duplicate rule is gone (`e4854a1`).

## 2. Verified clean

- **Windows**: half-open, whole local calendar days, one place.
- **Unknown vs zero**: tokens NULL, route zero rendered `—`, credits missing rendered `-`.
- **Concurrency**: no lock, but WAL plus `INSERT OR IGNORE` and a 10 s timeout; two concurrent
  syncs produced no duplicate rows and no error.
- **SQL**: identifiers from literals; values bound.
- **Test isolation**: `_hermetic.py` refuses reads of the real host directory (verified by
  tripping it).
- **Documents**: 406 tests in all three places; the 11 test classes named by `AGENTS.md` exist.

## 3. Standards deviations found (fixed)

The Chinese README still described three things the English README had already removed — the
runtime row and the per-day sparkline, and the `API Total` column — because the bilingual guard
compares structure, never prose (`a03ae37`). The English README's "18 calls across 3 servers" is
19 on this machine (`7484cfa`). `docs/maintenance/baseline.md` is a dated snapshot and was left
internally consistent rather than partially updated.

## 4. Open after this round

- `index_file`'s tail strategy assumes a legal JSON prefix cannot be the truncation point.
- `ensure_schema` issues DDL (drop/create views) on every sync; a long lock wait can still fail.
- `restore` deletes `-wal`/`-shm` while a TUI may hold the database; the documentation asks the
  user to close it first, and that was not exercised.
- `q_usage_kpi` still builds `credits`/`original_credits` with `or 0.0`; no caller reads them
  today, but the shape is the same "unknown as zero" this family forbids.
- The subprocess-side environment list still does not require `QCUT_CONFIG`, so a future case that
  shells out without pinning it would read the maintainer's settings.
